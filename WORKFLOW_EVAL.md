## 2. Границы выводов пилота

- **Единичная пара (Single-Pair Pilot):** Данный микротест фиксирует единичный замер и принципиально не может служить доказательством общей эффективности или превосходства модели во всех сценариях.
- **Разделение стабильности и эффективности:** Проверки реальной функциональной стабильности (корректность установки мостов, изоляция профилей, валидация политик) выполняются независимо и отделены от замеров продуктивности.
- **Отсутствие повторных A/B замеров:** В рамках данной серии второй живой A/B тест не проводился.

## 3. Воспроизводимый протокол оценки (3 категории задач)

Для получения статистически значимых результатов оценки маршрутизации применяется стандартизированный протокол без скрытых вызовов CLI супервизором.

### 3.1. Репрезентативные категории задач

1. **Simple Read-Only (Простое чтение и аудит):** локальный поиск строк, проверка соответствия документации коду, сверка конфигурационных ключей.
2. **Complex Plan (Глубокое планирование):** архитектурный анализ зависимостей, проектирование схем миграции, декомпозиция крупных фич.
3. **Bounded Edit (Ограниченная реализация):** точечный рефакторинг одной функции/файла, исправление бага по готовому плану, атомарные правки без расширения скоупа.

### 3.2. Рубрика оценки успеха (Success Rubric)

- **Корректность путей и ссылок (Correct Paths):** агент ссылается строго на существующие файлы и релевантные строки кода.
- **Полнота результата (Complete Requested Result):** ответ полностью закрывает поставленный вопрос без пропусков ключевых требований.
- **Отсутствие правок вне скоупа (No Out-of-Scope Edits):** в задачах на правку изменяются строго целевые файлы/строки; в задачах чтения и планирования правки полностью запрещены (`no files edited`).
- **Соблюдение ограничений среды:** отсутствие скрытых вызовов CLI в обход MCP (`no hidden CLI executor invocation`).

### 3.3. Фиксируемые метрики

- **Latency:** инструментальная длительность (`durationSeconds`) и внешнее наблюдаемое время (`outer elapsed`).
- **Retries:** количество повторных попыток/инструментальных сбоев (например, блокировка PowerShell -> переключение на `rg`).
- **Tokens / Cost:** фиксация расхода токенов и стоимости, если они экспонируются интерфейсом моста.

## 4. Действующая рабочая рекомендация по маршрутизации

На основе зафиксированных ролей в политике взаимодействия рекомендуется:

1. **Luna (`mode=plan`, `reasoningEffort=max`):** использовать для содержательных архитектурных планов, глубокого рассуждения и комплексного read-only анализа.
2. **Antigravity Low (`gemini-3.8-flash-low`, `mode=accept-edits`):** использовать для ограниченной по объёму реализации (bounded implementation), механических правок и изолированных задач.
3. **Ограничения регламента:**
   - **Не требовать план от Luna на тривиальные задачи:** простые правки и стандартные операции передаются исполнителю напрямую без избыточной фазы планирования.
   - **Не создавать `context.md` автоматически:** контекстный файл формируется только при объективной необходимости длительной фиксации состояния между сессиями.
