# Gemini and Codex: установка на Windows

Этот скрипт подключает [codex-antigravity-subagent](https://github.com/IlleJiViN/codex-antigravity-subagent)
к Codex через MCP и устанавливает глобальную инструкцию автоматического
делегирования. Ты общаешься с Codex как обычно, а он передаёт подходящие
самостоятельные подзадачи Antigravity и проверяет результат.

## Что должно быть установлено

- Windows PowerShell 5.1 или PowerShell 7.
- [Node.js](https://nodejs.org/) версии 20 или выше.
- [Git](https://git-scm.com/downloads/win).
- Codex CLI в PATH либо расширение Codex в VS Code.
- Официальный [Antigravity CLI](https://antigravity.google/docs/getting-started?tab=cli), команда `agy`.

Один раз войди в Google через интерактивный `agy`. Авторизация не переносится
между ПК. Если Antigravity запрашивает разрешение на команду, настрой конкретное
разрешение в самом Antigravity; установщик не включает обход подтверждений.
Node.js, Git и клиентов установщик проверяет, но сам не устанавливает.

## Установка

Скопируй эту папку на другой ПК или клонируй репозиторий. Открой PowerShell в
папке со скриптом. Права администратора не требуются.

Самый простой запуск — двойной щелчок по **`start.cmd`**. Он устанавливает
подключение, затем запускает одну настоящую проверку через MCP → `agy` → модель.
Окно остаётся открытым: ты увидишь выбранную модель, ожидание, уникальный код,
ответ CLI, длительность и расход токенов, сообщённый самим CLI.
Проверка расходует лимит Antigravity: одна задача Flash Low, до 120 секунд.

Сначала можно посмотреть, что будет сделано, без загрузки и изменения файлов:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\setup-antigravity.ps1 -WhatIf
```

Установить и включить:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\setup-antigravity.ps1
```

`ExecutionPolicy Bypass` действует только для этого процесса PowerShell.
Обвязка скачивается в каталог Codex, версия закреплена на коммите
`712480f2e0a744807fc59f1899812b4725289d92`. Используется готовый bundle;
сборка и `npm install` не нужны. При установке нужна сеть.

По умолчанию скрипт использует `%USERPROFILE%\.codex`; если задан `CODEX_HOME`,
использует его. Другой каталог можно передать параметром `-CodexDirectory`.

Параметры выбора моделей:
- `-LowModel` — быстрая модель для простых или ограниченных по объёму задач (по умолчанию `gemini-3.8-flash-low`).
- `-HighModel` — глубокая модель для сложных задач и масштабных изменений (по умолчанию `gemini-3.8-flash-high`).
- `-Model` — обратно совместимый параметр; если указан без явного `-LowModel`, он переопределяет низкоуровневую модель, сохраняя значение `-HighModel` по умолчанию.
- `-TimeoutSeconds` — таймаут выполнения делегированной задачи (по умолчанию 300 секунд).

Список доступных моделей можно посмотреть командой `agy models`.

После установки перезапусти расширение Codex (или CLI) и открой новый чат.
В нём дай обычную содержательную задачу, например: «Посмотри ТЗ и найди
неясные требования». Проверь, что Codex вызвал `agy_check` и `agy_delegate`.

### Роли и модель взаимодействия (Strict Supervisor Mode)

Устанавливаемая политика фиксирует строгое распределение ролей:
- **Codex — супервизор и аналитик**: Codex делегирует начальное исследование проекта, реализацию изменений, промежуточные проверки и написание тестов исполнителю Gemini (через Antigravity), а сам лишь формулирует задачи, анализирует отчёты и принимает результаты. Codex не выполняет рутинное исследование, редактирование файлов или тесты самостоятельно.
- **Gemini (Antigravity) — владелец реализации (implementation owner)**: отвечает за фактический поиск, редактирование кода и запуск тестов.
- **Прямое выполнение действий Codex'ом**: разрешено исключительно в виде узкого технического исключения, когда наглядно доказано, что Gemini технически не может выполнить конкретное действие (например, отказ в правах на запуск команды в headless-окружении). При этом Codex обязан явно раскрыть пользователю причину и техническое ограничение; тихий перехват упавшей задачи (silent fallback) строго запрещён.
- **Если MCP выключен или недоступен**: Codex сообщает пользователю о невозможности выполнения задач (execution is unavailable). Codex не пытается скрытно запускать `agy` через шелл и не выполняет работу руками вместо агента (разрешён только диалог и анализ уже имеющегося в контексте материала).
- **Режимы `mode` и уровни моделей**: режимы выполнения `mode=plan` (исследование, анализ и предложения без модификации файлов) и `mode=accept-edits` (авторизованная реализация и редактирование) полностью независимы от уровня модели (`-low` / `-high`). Уровни рассуждений выбираются исключительно суффиксом имени модели (параметр `model`), а не вымышленными аргументами вызова инструмента.

## Управление

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\setup-antigravity.ps1 -Action Status
powershell -NoProfile -ExecutionPolicy Bypass -File .\setup-antigravity.ps1 -Action Test
powershell -NoProfile -ExecutionPolicy Bypass -File .\setup-antigravity.ps1 -Action Disable
powershell -NoProfile -ExecutionPolicy Bypass -File .\setup-antigravity.ps1 -Action Enable
powershell -NoProfile -ExecutionPolicy Bypass -File .\setup-antigravity.ps1 -Action Uninstall
```

Включение/выключение применяется после перезапуска расширения/CLI и нового
чата. `Disable` отключает MCP и удаляет наше правило из глобальных инструкций.
`Enable` возвращает их. Это не переключатель уже запущенных задач; выключение
не прерывает Antigravity, если он уже работает.

`Status` показывает установленную конфигурацию, но не запускает модель.
`Test` отправляет случайный код через установленный MCP-сервер и принимает
успех только при точном совпадении ответа, успешном завершении и отсутствии
отклонённых действий. При выключенном режиме проверка не запускается.
Исходный запрос и ответ сохраняются в `logs/*.json`; путь выводится в терминал.
Тест подтверждает работоспособность цепочки, но доступность инструмента в
текущем чате нужно проверить после перезапуска расширения.

В постоянной инструкции включены правила экономии: компактный контекст и
отчёт, один исполнитель на задачу, проверка существенных результатов вместо
полного повторения работы, максимум один обоснованный повтор после ошибки при наличии конкретного исправления.
Перед делегированием Codex должен показать задачу и выбранную модель, после — фактический статус,
вызовы инструментов, число задач к числу повторов и длительность, если она есть в ответе инструмента. Процент экономии не обещается.

## Сохранение настроек и ограничения

Скрипт меняет только собственные помеченные блоки в `config.toml` и глобальных
инструкциях. Правило ставится в начало действующего `AGENTS.md` либо непустого
`AGENTS.override.md`, чтобы попадать в ограничение размера инструкций.
Остальное содержимое сохраняется:
- Если пользователь вручную добавил сторонние или дублирующие глобальные инструкции вне нашего управляемого блока (`<!-- >>> gemini-and-codex delegation >>> -->`), они остаются полностью нетронутыми.
- Локальные проектные правила и ограничения учебных проектов (например, запрет выдавать готовые решения студентам) обладают безусловным приоритетом над общими правилами делегирования.
- Перед изменениями создаются резервные копии в `<каталог Codex>\backups\antigravity-*`; при ошибке записи файлы восстанавливаются.
- Повторная установка не дублирует блоки. Чужую таблицу `antigravity_delegate` скрипт не перезаписывает. Изменённую установленную обвязку не обновляет.
- **Отсутствие программных гарантий**: системный промпт задаёт политику поведения агента, но не даёт строгой программной гарантии со стороны среды (software guarantee), что модель выполнит делегирование во всех возможных сценариях.

`Uninstall` удаляет наше подключение и правило. Скачанный исходный код и
резервные копии остаются на диске. Это не удаление всей конфигурации Codex.
